# Closing out #44, #101 and #102 — design

Three independent issues, three branches off `main` at `c974dc0`, three PRs. The
user delegated the decision on each to this design; the recommendations below are
the decisions, with the evidence they rest on.

Every claim about a run in this document and in the PR bodies resolves the run id
to its build and that build's branch before it is quoted (CLAUDE.md lesson 9).

## #44 — accept "one browser per OS", close, convert the arm into a contract guard

### Decision

The fonts half of #44 is documented behaviour, not a defect. Close #44 as resolved:
the WebGL half is fixed and measured; the fonts half has a runtime warning naming the
mechanism and the workaround, shipped on `main` since `8f36f9b` (2026-08-28,
*"fix(#45): one browser per OS, and stop masking the font failures it caused (#73)"*).

Evidence that this is already the product's contract, not a new choice:

- `pythonlib/camoufox/utils.py:703` `warn_fonts_excluded_by_launch` states that the
  launch-level font list becomes a process-wide whitelist, a per-context
  `setFontList()` can only narrow it, and the caller should launch one browser per
  OS. It is called from both `sync_api.py:219` and `async_api.py:230`, in-process,
  before `browser.new_context`.
- `service-tester` already groups contexts by OS into separate browsers for this
  reason.
- Five smoke runs on the #44 headline arm (34618162525, 34620762155, 34656256911,
  34658431749, 34678025310 — all on build 34578327006, branch
  `fix/95-cmap-unicode-ucs4`, except the last, on `main`'s merge of it) showed the
  same rule every time: the context matching the **launch** OS resolves its markers,
  the other two resolve none. The warning fired three times in every run.

The alternative — making the launch mask per-context in C++ — is rejected for this
pass: it widens a gate that has had three rounds and still fails open at context 0
(lesson 5), for a scenario the product already tells the caller not to use.

### What the arm becomes

`.github/workflows/smoke.yml`, step *"NewContext(os=X) is cross-signal coherent
(#44 headline)"*. It currently asserts the **unsupported** behaviour (every context
resolves its own markers) and is `continue-on-error: true` because that is known
red. It is rewritten to assert the **documented contract**, and `continue-on-error`
is removed. New name: *"mixed-OS contexts from one launch honour the launch font
mask, warn, and keep WebGL per-context (#44 contract guard)"*.

Verdict conditions, all collected then asserted at the end (never inline):

1. **Launch-OS context resolves its own markers.** Read `spoofed_os` from the
   reassembled launch config (already logged as `[launch] ... spoofed_os=`). The
   context whose `os=` matches must resolve all three of its marker families.
2. **The other two contexts resolve no markers at all** — not their own (the mask
   holds) and not any other set's (no cross-OS leak).
3. **`warn_fonts_excluded_by_launch` fired for exactly the two non-matching
   contexts.** Captured with `warnings.catch_warnings(record=True)` +
   `warnings.simplefilter("always")` around each `AsyncNewContext` call; match on
   the message substring `"can only narrow it, never restore a family (#44)"`.
   The matching context must produce zero such warnings.
4. **WebGL stays per-context.** Distinguish two failure shapes: every context's
   renderer equal to the launch config's renderer is the original #44 WebGL bug →
   RED; two contexts sharing a renderer that is *not* the launch's is a preset
   collision → SETUP-INVALID, not a verdict. Read the launch renderer from the same
   reassembled launch config.

Setup-invalid conditions kept from the current arm (no GL, absent-reference
resolving, platforms not distinct, probe dead via `base <= 0`) plus the collision
case above.

**Marker validity is made deterministic.** A new precheck inside the same step, run
before the headline launch: for each of `macos`, `windows`, `linux`, launch
`AsyncCamoufox(os=<that>)` and open one context with the same `os=`; all three of
that OS's marker families must resolve. Three extra launches, ~10 s each. This
closes the *"lin set never observed resolving"* gap for good — the guard no longer
depends on a random draw — and validates mac/win the same way. A precheck failure is
SETUP-INVALID for the whole step, since the headline cannot read markers it has not
shown to work.

The step's *"BEFORE FLIPPING THIS BACK TO BLOCKING"* comment is deleted; both items
in it land in this change.

### Evidence required in the PR

- Two smoke runs on the final branch commit against build 34578327006: the guard
  must be GREEN on both, and the two runs must show at least two distinct launch
  draws (dispatch until they do; each run prints `spoofed_os=`).
- One run must show the precheck's `lin=[...]` row with all three linux markers, so
  the linux set is finally observed resolving.
- A demonstrated RED: temporarily invert condition 2 on a scratch commit (assert
  the non-matching contexts *do* resolve), dispatch, quote the failure, revert. A
  guard that has never gone red is not evidence (lesson 4).
- Quote the `[launch] fontconfig=... spoofed_os=...` line from each run (lesson 8).

### Issue hygiene

- Close #44 with a comment: what was accepted, why, `8f36f9b` cited, the arm's new
  role, and where the remaining thread lives.
- File a new issue for the **context-0 fail-open** (lesson 5): `CamouIsFontAllowed`
  treats context id 0 as "no per-context list" and allows every family; four hops
  fail silently to 0. Short, cites the lesson text, no fix proposed.

## #101 — measure first; the measurement chooses

### The question

Are dot-prefixed family names CSS-addressable in a mac-list context on this build?
Real macOS hides them (`CTFontManagerCopyAvailableFontFamilyNames()` returns none;
Gecko refuses them by name at `CoreTextFontList.cpp:1425`), so on a real Mac a page
asking for `.LastResort` by name gets the generic fallback. If they resolve by name
here, the 49 entries in `fonts.json['mac']` are a live enumeration tell.

### The measurement

Branch `meas/101-dot-names`, one commit adding a diagnostic probe (no assert) beside
the #95 discriminator, same `mac_list_probe` and `PIXEL_JS`, families `.LastResort`,
`.SF NS`, `.PingFang HK`, `.Aqua Kana`, `.Helvetica LT MM` plus the absent reference
and `Helvetica Neue` as positive control. Smoke run **34681622483** against build
34578327006 (`fix/95-cmap-unicode-ucs4`).

### Decision rule

- **Any probed dot-name differs from the absent reference** → they are addressable by
  name → remove all 49 dot-prefixed entries from `fonts.json['mac']`. Blast radius:
  `_ESSENTIAL_FONTS_MACOS` (16 names) contains no dot-name, so only the 30–78%
  random non-essential sample changes. Every smoke arm loads `FONTS` from that file,
  so the PR needs a full smoke run to show no arm moved for a reason other than the
  49 names.
- **All five equal the absent reference** (with the positive control differing) →
  inert for by-name enumeration → do not touch `fonts.json`; add a note to #101
  recording the measurement and downgrade it to a documentation item.

Either way the PR body states the tension recorded in #101 itself: removing
`.LastResort` from the list makes a mac-list context unable to reach it in fallback,
which real macOS can. The tell being chosen is by-name enumeration (49 names) over
the fallback glyph shape of one face; say so.

### Resolution — run 34681622483 (build 34578327006, `fix/95-cmap-unicode-ucs4`)

```
[#101 dot-name probe] absent=1610098690 control(Helvetica Neue)=2304685864 control_differs=True
[#101 dot-name probe] '.LastResort':      checksum=1746458689 differs_from_absent=True
[#101 dot-name probe] '.SF NS':           checksum=3245174874 differs_from_absent=True
[#101 dot-name probe] '.PingFang HK':     checksum=1827617245 differs_from_absent=True
[#101 dot-name probe] '.Aqua Kana':       checksum=2450981184 differs_from_absent=True
[#101 dot-name probe] '.Helvetica LT MM': checksum=1061199180 differs_from_absent=True
```

All five resolve by name, each to a distinct face, with the positive control valid.
**Decision: remove all 49 dot-prefixed entries from `fonts.json['mac']`.** Branch
`fix/101-dot-names`.

This also falsifies a claim in PR #98's body — that `.LastResort` "is not addressable
from CSS". It was never measured; it is addressable, and it renders distinct pixels
by name. A correcting comment goes on #98 citing this run.

### What the fix must show

- `fonts.json['mac']` count `574 → 525`; the 49 removed names listed in the PR body;
  no non-dot name touched (diff is deletions only, each beginning with `"."`).
- A full smoke run on the branch against build 34578327006, GREEN, with the
  `[#101 dot-name probe]` lines showing the same five names now **equal** the absent
  reference in a mac-list context — the measurement inverted by the fix. The probe
  stays, gaining an assert on that condition (deferred through `tripwires`, never
  inline — lesson 9's corollary).
- The `#95 cmap discriminator` and `(cmap95)` guard unchanged and still green: Geneva,
  Apple Symbols, Heiti TC/SC are not dot-prefixed and stay in the list.
- Arm j2's `ctx=6 resolved=.LastResort` line is expected to be **unchanged**: that is
  the bare no-list context, which consults no list. State this in the PR so the
  reader does not take it as the fix failing.

## #102 — two edits; the first is not the two-line swap the issue promised

### What the issue got wrong

`Version` (`pkgman.py:338`) compares on `sorted_rel`, derived from the **build tag**
(`beta.31`), not the Firefox version. `PLAYWRIGHT_BROWSER_FLOORS` is
`(((1, 61), 'beta.30'),)` — the floor is a build tag. So `_bundle_verstr`, which
returns the Firefox major (`'152'`), is on the wrong axis entirely and cannot be
swapped in.

### The fix

`application.ini`'s `Version=152.0.4-beta.31` carries both halves. Add
`_bundle_version(path: Optional[Path]) -> Optional[Version]` next to
`_bundle_verstr`, reusing its file discovery (sibling `application.ini`, or
`../Resources/application.ini` for the `.app` layout), splitting the value on the
first `-` into `version='152.0.4'`, `build='beta.31'`, and returning
`Version(build=..., version=...)`. Returns `None` on any miss, never raises.

`warn_if_executable_predates_playwright` tries `_bundle_version(path)` first and
falls back to the existing `Version.from_path(path.parent)` so an unpackaged objdir
build with a `version.json` keeps working. No other behaviour changes.

### Tests (`pythonlib/tests/test_bundle_verstr.py`, same file, same fixtures)

- RED first: fake `application.ini` with `Version=152.0.0-beta.29` → the warning
  fires (floor is `beta.30` under Playwright ≥ 1.61; the test pins the resolved
  Playwright version via monkeypatch so it does not depend on the environment).
- Regression that matters: the real extracted binary at
  `/tmp/cf97/cf/Camoufox.app/Contents/MacOS/camoufox` → **0 warnings**. If parsing
  the beta suffix misreads a current package as below the floor, every
  `executable_path` user gets a spurious warning on every launch. This test is
  skipped, not failed, when that path is absent.
- `_bundle_version` unit cases: `.app` layout, flat layout, no `-` in the value,
  missing file, unreadable file.

Calling these functions directly never reaches the fetcher, so no download risk.

### The comment

`service-tester/run_tests.py`: the comment describing masking as `ApplyWhitelist()`
is rewritten to name the lookup-time AND-gate, citing `patches/font-hijacker.patch`'s
header. One comment, no code.
